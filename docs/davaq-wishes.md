# DavaQ 소원함 — 사기 전에, Q에게 먼저

갖고 싶은 물건·재능·경험을 먼저 정하고, 내가 제공할 수 있는 것으로 바꿀 경로를 찾는 기능이다. 홈·둘러보기의 안내 카드와 Q 대화 메뉴에서 시작한다. 소원 목록은 `/app/wishes`, 새 소원은 `/app/wishes/new`에 있다.

## 사용 흐름

1. 상품 캡처·사진을 선택하거나 원하는 것을 설명한다. 외부 쇼핑몰 URL에서 상품을 추출하거나 재고·가격을 조회하는 기능은 없다.
2. **Q로 정리하기**를 누르면 상품명·필수 검색어·종류·분야·설명의 초안이 만들어진다. 사진이 모호하면 추가 질문이나 빈 항목이 나올 수 있다. 사용자가 직접 확인·수정한 뒤 저장한다. 분석 실패 시에도 수동 입력으로 저장할 수 있다.
3. 저장한 소원에서 **내가 줄 것 / 내가 받을 것**을 먼저 확인한다. 직접 교환과 3~4명이 이어 바꾸는 후보를 함께 보여준다.
4. 후보를 선택하면 기존 교환 제안 화면으로 이동한다. 일정·장소·상태·제공 범위를 직접 확인하고 제안해야 상대방과 교환을 논의할 수 있다. 후보 발견이나 소원 저장만으로 제안·동의·예약이 발생하지 않는다.
5. 소원은 수정, 잠시 쉬기, 다시 찾기, 구했어요, 삭제로 관리한다. 삭제하지 않은 소원은 계정당 최대 50개다. 소원 상태 변경·삭제는 이미 생성한 교환 제안을 변경하거나 취소하지 않는다.

내가 공개한 제공 항목이 없으면 물건·재능 등록을 안내한다. 목표와 비슷한 상품이 있어도 연결 조건이 맞지 않으면 이를 완성된 교환 후보로 표시하지 않는다. 후보가 없을 때는 검색어 수정과 제공 항목 추가를 안내한다.

## 사진과 공개 범위

소원 목록·상세·사진은 본인만 조회한다. 서버는 본인이 업로드한 교환 이미지인지 확인한다. 허용 형식은 JPEG·PNG·WebP, 최대 크기는 8MB이며 분석 전 실제 파일 형식과 크기도 검사한다.

사진 선택만으로 업로드하거나 분석하지 않는다. **Q로 정리하기** 또는 **소원 저장**을 누르면 선택한 사진을 DavaQ에 업로드한다. **Q로 정리하기**를 누를 때에만 입력 설명과 첨부 사진을 OpenAI에 보내 초안을 생성한다. 수동 저장과 교환 후보 검색은 사진 분석을 호출하지 않는다. 상품이 잘 보이는 이미지를 사용하고, 주문번호·결제정보·타인의 얼굴 등 상품과 무관한 정보는 가리도록 안내한다.

소원 삭제는 제목·설명·검색어·이미지 연결을 지우고 이후 조회·검색에서 제외한다. 업로드 저장소의 원본 파일을 즉시 물리 삭제하는 기능은 아니다. 사용자가 교환을 제안한 뒤에는 해당 교환의 물건과 조건을 참여자가 확인하며, 소원 검색이 기존 공개 등록의 희망 조건을 자동으로 바꾸지는 않는다.

## 후보를 찾는 기준과 한계

현재 DavaQ에 공개된 실제 제공 등록만 검색한다. 임시·숨김 등록, 차단 관계, 이미 예약된 물건은 제외한다. 종류·분야가 같아야 하며 상품명과 검색어에서 추출한 유효 단어를 모두 만족하는 **AND 조건**을 적용한다. 검색어는 동의어를 여러 개 나열하는 목록이 아니다. 상품명은 짧고 정확하게, 꼭 필요한 모델명·특징을 검색어에 넣고 용도·상태 등 희망 조건은 설명에 적는다.

예를 들어 `헤드폰, WH-1000XM5`는 두 조건을 모두 확인한다. 숫자가 포함된 모델 식별자는 제공 등록 제목에서 확인하며, `XM5`를 `XM50`으로 잘못 연결하지 않도록 검사한다. 본품을 원하는 경우 케이스·빈 상자 등 액세서리 등록도 걸러낸다. 다만 글 기반 후보이므로 정품·정확한 모델·구성·상태를 인증하는 기능은 아니다.

내 제공 항목과 상대의 희망 조건을 대조하여 직접 교환을 찾고, 3~4명 경로에서는 각 참여자의 교환 조건과 차단 관계를 확인한다. 검색량에 상한이 있어 전체 등록·모든 경로를 빠짐없이 탐색한다고 보장하지 않는다. 일부만 검색한 경우 화면에 안내한다. 제공 범위, 실제 제품, 일정과 전달 장소는 참여자들이 확인해야 하며 교환 성사를 보장하지 않는다.

## 자동 검색과 Q 알림

- 기존 **내 AI → 자동 매칭** 설정(`agent_settings.auto_search`)이 켜진 계정의 활성 소원만 자동 검색한다. 기본값은 꺼짐이다. 소원 상세에서 `/app/agent/settings`로 이동할 수 있다.
- 기존 에이전트 작업기가 약 1분마다 실행되며, 검색할 차례가 된 소원을 한 번에 최대 2개 가져와 순차 처리한다. 검색 후 다음 검색까지 15분을 두므로 각 소원이 정확히 15분마다 처리되는 것은 아니다. 대기량과 서버 상태에 따라 늦어질 수 있다.
- 수동 검색도 다음 자동 검색 시점을 15분 뒤로 미룬다. 처리 실패 시에는 5분 뒤 재시도 대상이 된다.
- 새 직접 교환 또는 이어 바꾸기 경로가 발견되면 본인의 Q 대화에 소원 카드가 남는다. 같은 경로 집합의 중복 카드를 막으며, 소원별 새 알림은 최대 시간당 1회다. 앱 밖 푸시 알림 발송이나 상대방에게 자동 제안하는 기능은 아니다.
- 결과 저장 직전에 활성 상태·소원 버전·자동 매칭 설정과 동의 버전을 다시 확인한다. 중간에 소원을 수정·중지·삭제하거나 자동 매칭을 끄면 이전 작업 결과로 알림을 만들지 않는다.

## 운영 확인

마이그레이션 `0038_davaq_wishes.sql`은 별도 `exchange_wishes` 테이블과 소원 기반 이어 바꾸기 조건을 저장할 `exchange_relays.goal_context`를 추가한다. AnotherMe 데이터베이스와 공유하지 않는다.

인증된 `/api/exchange/wishes`에서 생성·목록 조회를, `/:id`에서 본인 상세 조회·버전 기반 수정을, `/:id/candidates`에서 후보 검색을 제공한다. `/draft`는 초안 생성이며 시간당 12회로 제한한다. 초안 생성은 기존 OpenAI 연결과 `DAVAQ_AI_MODEL` 설정을 사용하고 `store: false`, 35초 제한, 자동 재시도 없음으로 호출한다.

자동 검색은 기존 DavaQ 에이전트 작업기에 포함된다. 작업기 시작 여부와 DB 마이그레이션을 확인하고, 문제가 생기면 `DavaQ wish search unavailable` 또는 `DavaQ worker unavailable` 로그를 확인한다. 모델 장애가 있어도 수동 소원 입력과 등록 글 기반 후보 검색은 사용할 수 있다.

UI 검증은 실제 소원 화면과 합성 데이터·분석 응답을 사용한 격리 환경에서 수행했다. 320/390px 화면, 사진 선택·초안 수정·저장, 직접/이어 바꾸기 진입, 후보 없음, 제공 항목 없음, 수정·일시중지·재개, 분석 실패의 수동 입력 전환을 확인했다. 실제 사용자 데이터나 유료 모델 호출은 UI 검증에 사용하지 않았다.
