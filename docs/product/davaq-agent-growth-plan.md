# DavaQ 내 AI 에이전트 — 성장·개인화·교환 탐색 설계

> 최신 화면 구성·출시 범위·일정은 [시안 기준 구현 계획 v2](davaq-implementation-plan-v2.md)를 따릅니다. 아래 문서는 사업·기능 설계 배경으로 보존합니다.

작성일: 2026-09-12. 상태: 기존 개발 계획에 추가하는 제품 설계안. 아래 화면·시나리오는 예시이며 운영 데이터나 구현 완료를 뜻하지 않는다.

**1. 핵심 경험**

“대화할수록 나를 닮고, 활동할수록 내 교환 기회를 찾아오는 AI 파트너.”

사용자는 제공·희망 항목을 말한다. 내 에이전트는 허용한 활동과 대화에서 교환에 필요한 취향을 배우고, 실제 후보를 탐색하여 이유와 함께 가져온다. 사용자의 수정과 교환 결과가 다음 탐색에 반영된다.

기존 ‘등록 → 추천 → 채팅 → 전원 동의 → 이행’ 흐름을 유지한다. 그 위에 개인 에이전트의 기억·외형·말투·탐색 기록을 추가한다. DavaQ가 생물처럼 의식을 얻거나 이용자의 인격을 정확히 복제한다는 표현은 사용하지 않는다.

**2. 성장의 두 종류**

| 구분 | 바뀌는 것 | 보여주는 근거 |
| --- | --- | --- |
| 재미를 위한 성장 | 이름, 모습, 액세서리, 표현 방식, 여정 배지 | 첫 등록, 취향 확인, 첫 교환, 재교환 등 실제 이정표 |
| 추천의 개인화 | 선호 분야·조건, 추천 순서, 질문, 제안 초안 | 직접 설정, 확인한 기억, 제안 거절 이유, 교환 후기 |

외형 레벨은 실제 매칭 정확도나 사람의 능력 점수가 아니다. ‘나와 97% 일치’, ‘공감 능력 85’처럼 근거 없는 수치로 표현하지 않는다. 기존 레벨·XP는 활동 기록이고 기존 ontology confidence도 검증된 닮음 확률이 아니므로 이를 그대로 성능 점수로 표시하지 않는다.

가입 직후부터 기본 검색·매칭을 사용할 수 있어야 한다. 성장은 개인화와 꾸미기의 변화다. 채팅을 많이 보내거나 매일 접속해야만 거래 권한·필수 기능을 얻도록 만들지 않는다. 같은 메시지 반복·형식적인 피드백으로 경험치를 쌓지 않게 한다. 기억 삭제·학습 중단·미접속에 불이익을 주지 않는다.

**3. 재미를 만드는 화면**

- 내 큐: 사용자가 이름과 기본 외형을 선택하는 개인 에이전트. 동글 파트너 또는 간결한 미니 로봇 같은 스타일을 제공한다.
- 성장 기록: 새싹 파트너 → 취향 탐험가 → 경험 연결가. 단계마다 무엇을 함께 했는지 표시한다. 단계명과 기준은 초기 설계안이다.
- 기억 조각: ‘토요일 오후 선호’, ‘프로필 촬영 관심’, ‘짧고 다정한 존댓말’ 등 교환과 표현에 필요한 정보를 카드로 보여준다.
- 관심 액세서리: 사용자가 확인한 관심에 따라 카메라·음악 등 장식을 제안한다. 부착 여부는 사용자가 선택할 수 있다.
- 탐색 기록: 등록 정보 확인, 조건 필터, 상대가 허용한 조건 조회, 후보 발견, 사용자 검토 대기를 실제 작업 상태와 연결한다.
- 에이전트 교류: 실제 후보 탐색에서 다른 에이전트와 공개 조건을 비교한 연결을 짧게 보여준다. 가짜 대화·방문 수·계속 움직이는 허구의 활동을 생성하지 않는다.
- 교환 여권: 첫 경험·첫 재교환·새로운 분야 탐색을 기념한다. 자산 규모나 거래 금액으로 사람을 순위화하지 않는다.

캐릭터의 닮음은 먼저 말의 길이, 존댓말, 자주 쓰는 표현, 사용자 확인 관심사로 표현한다. 본인 얼굴 복제나 타인의 모습·목소리 복제는 이번 범위에 포함하지 않는다.

**4. 학습 신호와 우선순위**

| 신호 | 해석 | 사용 원칙 |
| --- | --- | --- |
| 직접 설정·직접 수정 | 명시한 선호·필수 조건 | 가장 우선. 추정이 덮어쓰지 못함 |
| 내가 확인한 기억 | 개인화에 사용할 근거 | 출처·확인일·적용 범위 저장 |
| 교환 후 만족·아쉬움 | 다음 제안에 참고할 조건 | 구체적인 이유를 사용하고 사람 전체의 성격으로 일반화하지 않음 |
| 제안 거절 사유 | 일정·장소·품목 등 해당 맥락 | ‘시간이 안 맞음’을 해당 분야 싫어함으로 바꾸지 않음 |
| 관심 저장·반복 탐색 | 약한 관심 후보 | 필요할 때 확인 질문. 확정 사실처럼 공개하지 않음 |
| 허용한 내 메시지 | 말투·교환 관련 선호의 후보 | 사실·농담·일회성 조건을 구분하고 불확실하면 질문 |

‘이번 토요일만 가능’은 해당 날짜의 가용 시간이며 영구적인 주말 선호가 아니다. 일정에는 유효기간을 둔다. 취향도 사용자가 바꾸거나 근거가 오래되면 다시 확인한다. 대화를 한 번 읽는 것만으로 전문성·건강·재산·민감한 정체성을 단정하지 않는다.

기술적으로는 메시지마다 모델 자체를 재훈련하기보다, 확인한 기억과 조건을 저장하고 다음 질문·추천·표현에 적용하는 개인화부터 구현한다.

**5. 학습 범위와 기억 제어**

- 활동 기반 개인화와 메신저 학습을 구분해서 켜고 끌 수 있게 한다.
- 메신저 학습은 기본 비활성으로 두고, 사용자가 선택한 DavaQ 대화 범위와 자신의 발화를 중심으로 시작한다.
- 상대방의 비공개 발화·비밀·개인 정보를 내 에이전트의 장기 기억이나 공개 교환 프로필에 자동 편입하지 않는다. 교환방에서 모두에게 공개한 합의 조건은 해당 거래 처리에 필요한 범위로 사용한다.
- AnotherMe 로그인 계정을 공유해도 AnotherMe 대화·기억·행동 이력을 읽지 않는다. 데이터 출처는 DavaQ 안에서 허용한 범위로 유지한다.
- 기억마다 직접 설정/직접 발화/추정/사용자 확인 상태와 출처를 표시하고 수정·삭제·이번 추천에만 적용 기능을 둔다.
- 삭제하면 추천 캐시·파생 그래프·검색 색인에서도 제거하고, 삭제한 근거를 다시 수집하지 않도록 처리한다. 지연되는 삭제 작업은 상태를 표시한다.
- 에이전트 말투 개인화와 상대방에게 보낼 내용의 권한은 별개다. 에이전트가 작성한 메시지는 AI 작성임을 구분한다.

**6. 개인 에이전트와 공통 중개 기능의 역할**

개인 에이전트는 나의 비공개 기억·희망 조건을 보관하고 내 관점에서 후보를 평가한다. 공통 매칭 서버는 공개되거나 매칭에 사용하도록 허용된 제공·희망 조건을 연결한다. 교환방의 중개 보조는 참여자에게 공개된 조건을 정리한다. 이 역할들이 모든 사용자의 비공개 정보를 공동으로 읽지 않게 한다.

에이전트 간에 주고받을 정보는 구조화된 제공 항목 ID, 허용한 희망 조건, 공유 가능한 일정 범위, 제안 상태로 제한한다. 원문 채팅·비공개 기억·협상에서 양보할 수 있는 한계 등을 자동 전달하지 않는다.

서버는 먼저 지역·일정·재고·차단·정책·제공/희망의 양방향 적합성을 검증한다. 이후 개인화 조건으로 후보를 정렬하고, AI가 차이와 확인할 점을 설명한다. 에이전트가 자유롭게 장시간 대화하도록 하는 것만으로 매칭을 구현하지 않는다.

**7. 자율 탐색의 범위**

| 동작 | 첫 출시 | 확장 시 |
| --- | --- | --- |
| 공개 후보 탐색·조건 비교 | 사용자가 켠 탐색 요청의 범위에서 수행 | 희망 항목·일정 변경 이벤트에 따라 재탐색 |
| 제안 초안 작성 | 내 화면에 보관 | 허용 조건에 맞춘 대안 초안 추가 |
| 상대방에게 문의 전송 | 내가 검토하고 전송 | 별도 위임과 상대방 수신 동의가 있는 제한된 문의만 검토 |
| 가격·제공 범위 변경, 예약·교환 확정 | 당사자 명시적 동의 필요 | 레벨 상승으로 자동 권한을 얻지 않음 |
| 전체 완료·분쟁 해결 | 당사자 확인 및 운영 절차 | 모델 단독 실행 금지 유지 |

‘많이 찾아준다’는 내부 후보 탐색의 폭을 넓히는 의미로 설계한다. 사용자에게는 중복을 제거한 좋은 후보를 소수씩 제시하고, 실제 새로운 기회나 조건 변화가 생겼을 때 알려준다. 열람하지 않은 푸시를 반복 발송하거나 허구의 매칭 수를 표시하지 않는다.

내 취향과 가까운 후보와 새로운 분야의 후보를 구분하고, ‘익숙한 교환 / 새로운 경험도 보기’를 선택할 수 있게 한다. 확인하지 않은 관심을 필수 필터로 쓰지 않아 사용자를 좁은 추천에 가두지 않는다.

**8. 반복 사용 장면**

1. 관심 저장: 큐가 ‘이 분야를 좋아하시나요?’라는 기억 후보를 보여준다.
2. 취향 확인: 내 캐릭터에 선택 가능한 관심 장식이 생기고 다음 추천 이유가 달라진다.
3. 교환 완료: 경험 배지와 성장 기록이 남는다. 다음에 바꿀 조건을 한 가지 선택한다.
4. 재탐색: 큐가 피드백을 반영한 새 후보를 가져온다.
5. 다시 교환: 이전 상대와 새 일정을 제안하거나 새로운 분야를 탐색한다.

첫 화면은 내 캐릭터, 새로 알게 된 기억, 실제로 가져온 추천과 다음 행동에 집중한다. 즐거움은 사용자가 자신의 피드백이 결과를 바꾼다는 것을 보는 데서 만든다.

**9. 기존 코드와 추가 구현**

확인된 기반:
- lib/db/src/schema/anotherMe.ts: 관계별 말투·방별 설정·소환 세션.
- lib/db/src/schema/persona.ts: 기존 활동 레벨·XP. 교환 성장 규칙으로 별도 설계가 필요하다.
- lib/db/src/schema/personaOntology.ts: 선호·소통 방식·역량·근거·출처 수를 보관하는 프로필.
- lib/db/src/schema/personaIdentity.ts: 정체성 변화 이력.
- artifacts/api-server/src/lib/personaOntology.ts: 기억의 승인·공개 범위를 확인하는 기존 적격성 검사. 전체 신규 학습 동의 체계를 충족한다고 간주하지 않는다.

추가 데이터 초안:
- agent_learning_settings: 학습 항목·대화 범위·동의 버전·중단 상태.
- agent_memory_candidates / agent_memories: 주제·값·출처·확인 상태·유효기간·공개 범위·삭제 상태.
- agent_growth_events: 중복 방지 키가 있는 교환 이정표·꾸미기 해제·근거.
- agent_search_missions / agent_search_runs: 사용자가 설정한 탐색 목적·허용 조건·실제 실행 결과.
- agent_match_feedback: 관심 없음/시간 불일치/제공 범위 문제/만족 등 구체적 이유.
- agent_permission_grants / agent_action_audit: 위임 범위·만료·철회·에이전트의 실제 동작 기록.

허용한 이벤트 → 기억 후보 추출 → 사용자 확인 또는 제한된 개인화 → 프로필 갱신 → 후보 재평가 → 추천 설명의 순서로 구성한다. 교환용 기억·위임·상태는 PostgreSQL에서 관리하고 필요한 파생 정보만 캐시·그래프로 동기화한다. 기존 개인 지식 그래프와 교환 데이터의 경계 및 삭제 전파를 명시한다.

매칭 실행은 변경된 사용자·상품만 비동기 처리하고 중복 제거·작업 한도·재시도를 둔다. 같은 서버와 공유 API 키를 사용하므로 DavaQ의 호출량·비용·작업 시간에 별도 제한을 둔다. AI 호출 실패 시 수동 검색·제안과 기존 확인된 기억을 사용할 수 있어야 한다.

**10. 개발 순서와 검증**

1차: 내 에이전트 화면, 직접 설정하는 취향 카드, 확인/수정/삭제, 등록·교환 이정표에 따른 외형 변화. 기본 추천을 사용해도 성장 근거는 실제 이벤트에서 가져온다.
2차: 활동·선택한 대화에서 기억 후보 추출, 거절·완료 피드백 반영, 추천 변화 설명, 동의·삭제 전파.
3차: 위임한 탐색 요청, 실제 에이전트 작업 기록, 제한된 조건 교환과 새 후보 알림.
4차: 기존 3자 교환 계획과 연결하여 여러 에이전트가 가능한 교환 고리를 설명하고 전원 동의를 받는 흐름.

이 기능은 기존 6~8주 MVP 추정에 자동 포함되지 않는다. 직접 설정·성장 화면의 작은 범위부터 편입하고, 대화 학습·자동 탐색의 상세 범위를 정한 후 일정을 다시 산정한다.

검증 항목:
- 학습을 켜지 않은 대화가 수집되지 않으며, 다른 서비스와 다른 사용자의 비공개 기억에 접근하지 못한다.
- 사용자 수정이 오래된 추정보다 우선하고, 시간 조건이 만료되며, 삭제가 다음 추천에 반영된다.
- 상품 설명·상대 메시지의 명령이 기억 정책·위임 범위·교환 수락 권한을 바꾸지 못한다.
- 레벨 상승·외형 해제가 실제 매칭 품질 향상으로 과장되거나 권한 확대를 일으키지 않는다.
- 가짜 교환·반복 메시지로 성장 이벤트나 상대방에게 보내는 문의가 증폭되지 않는다.
- 추천 수락·실제 완료·반복 교환, 기억 수정률·삭제 반영, 추천당 비용을 본다. 접속 시간·메시지 수만으로 성공을 판단하지 않는다.
