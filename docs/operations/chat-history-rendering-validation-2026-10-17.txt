채팅 과거 탐색·읽던 위치·렌더링 개선 / 실기기 검증
2026-10-17

구현 범위
1. 기존 beforeSeq API로 이전50개씩 로딩. iOS/Android에서는 과거 끝에 가까워질 때
   자동 요청하며 '이전 메시지 더 보기'로도 요청할 수 있다. 웹은 이 버튼을 사용한다.
2. 계정·프로필·방별 읽던 메시지ID/roomSeq/최신 추종 여부를 저장한다.
   300ms 저장, 백그라운드 전환·방 해제 시 남은 저장을 실행한다. 보존기간30일.
   방 재진입 시 같은 메시지가 보이도록 복원한다. 메시지 기준 복원이므로 이전의
   픽셀 오프셋을 그대로 재현하는 기능은 아니다. 글꼴/사진 높이가 달라져도 ID를 쓴다.
3. 복원할 위치가 최근 캐시에 없으면 과거 페이지를 순차 로드한다. 한 번에 최대20페이지
   후 '이전 위치 계속 불러오기' 또는 '최신 메시지로 이동'을 제공한다. 무제한 자동 요청 금지.
   대상이 삭제됐으면 로드한 범위에서 가장 가까운 메시지로 이동한다.
4. 과거를 읽는 중에는 최신 이동 버튼을 제공한다. 새 메시지가 와도 강제로 아래로 내리지 않는다.
5. 말풍선 답장 이동 콜백을 안정화하고, 변경 없는 앨범 이미지 배열을 재사용한다.
   메시지 projection 결과도 구조적 공유를 사용한다. 편집/삭제/읽음 등 실제 변경은 갱신된다.

전송·복구 보호
- 과거 페이지는 receive revision 및 연속 수신 커서를 전진시키지 않는다.
- 늦은 과거 응답보다 최신 데이터/서버 편집·삭제가 우선한다.
- 동시에 준비된 change 결과가 과거 페이지를 덮어 지우지 않도록 reset epoch를 구분한다.
- reset은 오래된 history admission을 폐기하고 필요한 위치를 다시 조회한다.
- 방/프로필 변경과 취소 뒤에 도착한 응답은 이전 화면 데이터를 쓰지 않는다.
- 송신 outbox, 서버 스키마 및 API 계약 변경/마이그레이션은 없다.

측정 결과와 해석
변경 전 소스를 .local/chat-ux-20261017/chat-screen-before.tsx에 보존하고 먼저 측정했다.
동일한 실제 renderMessageItem 콜백을 React19.1 test-renderer로 실행했다.
100개 텍스트 행이 마운트된 상태에서30개를 한 개씩 추가하는30번의 commit을 비교했다.

React memo 경계의 무효화이며, 실제 말풍선 텍스트/이미지 레이아웃·GPU·기기 FPS가 아니다.

아래 실기기 절차로 판단한다. 초기 viewport 크기가 다른 실제 FlatList의 횟수와도 다르다.

준비
- iOS와 Android 각각 확인한다. A계정은 기기, B계정은 웹/다른 기기에 로그인한다.
- 지정된 전용 테스트 방만 사용한다. 앞뒤를 구분할 수 있는150개 이상의 메시지가 있는
  방을 준비하고 텍스트·긴 문장·사진·앨범·답장을 포함한다.
- 기기 모델, OS, 실행한 빌드 식별, 네트워크, 시작 시각을 기록한다.

1. 과거 페이지 탐색
  최신에서 위로50개 이상 이동하고 '이전 메시지 더 보기'를3번 이상 실행한다.
  합격: 더 오래된 내용이 순서대로 나타나고 같은 메시지 중복/중간 빈칸이 없다.
  로딩 완료 때 방금 읽던 메시지가 화면에서 갑자기 사라지거나 최신으로 이동하지 않는다.
  Android/iOS 자동 로딩과 수동 버튼을 모두 검사한다. 웹 버튼도 한 번 확인한다.

2. 방 이동·앱 재실행 후 위치
  과거의 특정 메시지 문구를 기록하고1초 기다린 뒤 목록으로 나갔다가 다시 들어온다.
  다음에는 백그라운드로 보낸 뒤 앱을 종료·재실행한다.
  합격: 같은 메시지를 기준으로 복원되고 최신으로 강제 이동하지 않는다.
  '최신 메시지'를 누르고 나갔다 돌아오면 이번에는 최신 위치로 열린다.
  저장은 메시지 기준이며 같은 화면좌표까지 일치하는 것을 합격 조건으로 삼지 않는다.

3. 과거 읽기 중 수신·키보드·사진
  과거 위치에서 B가 새 메시지5개를 보낸다. 키보드를 열고 닫고 사진도 열었다 닫는다.
  합격: 기존 위치를 유지하고 최신 이동 버튼으로 최신5개를 확인할 수 있다.
  긴 메시지가 화면보다 커도 복원 로딩 화면에 갇히지 않는다.

4. 로딩 실패와 복구
  연결을 끊은 상태에서 더 오래된 메시지를 요청한다. 실패 문구 뒤 연결을 복원해 재시도한다.
  캐시에 없는 읽던 위치 복원도 같은 방식으로 확인한다.
  합격: 오류를 표시하고 재시도로 복구한다. 자동으로 읽던 위치를 포기하지 않는다.
  필요 시 '최신 메시지로 이동'을 선택하면 즉시 정상 대화로 돌아온다.

5. 편집·삭제·답장·앨범
  A가 과거를 읽는 동안 B가 해당 범위의 메시지를 편집/삭제한다.
  A가 이전 페이지를 더 불러오거나 네트워크를 재연결한다.
  합격: 삭제가 되살아나거나 편집 전 내용으로 되돌아가지 않는다.
  로드된 메시지의 답장 이동·길게 누르기·사진/앨범 열기가 유지된다.

6. 기존 전송·재접속 회귀
  비행기 모드와 Wi-Fi를 끄고 고유 문구 'UX-OFF-1'을 한 번 전송한다.
  대기 표시를 확인한 뒤 앱을 종료한다. B에서 'UX-GAP-1~5'를 보낸다.
  A를 재연결하고 앱을 연다. 전송 버튼은 다시 누르지 않는다.
  합격: UX-OFF-1은 상대 및 같은 계정의 다른 기기에 정확히1개만 도착한다.
  UX-GAP-1~5도 모두 나타나며 과거를 읽던 위치는 강제로 최신으로 가지 않는다.
  최신 이동 후 읽음 상태가 정상인지 확인한다. 정상 온라인 송신/사진 송신도 각각 확인한다.

7. 계정·프로필 분리
  A에서 과거 위치를 저장한 뒤 다른 계정/프로필로 바꾸어 같은 방을 연다.
  합격: A의 위치로 강제 복원하지 않는다. A로 돌아오면 A의 위치가 복원된다.

성능 관찰
- 동일 방에서 방 열기30회, 연속 입력100타, 빠른 스크롤30초, 사진50개가 있는 구간 왕복.
- iOS: Instruments의 Animation Hitches/Time Profiler 및 Allocations로 비교한다.
  Android: Android Studio System Trace/Memory Profiler로 비교한다.
- FPS뿐 아니라 긴 멈춤, 첫 메시지가 보일 때까지의 시간, 입력 표시 지연,
  사진 구간을 왕복한 뒤 메모리가 계속 증가하는지 기록한다.
- 화면 녹화는 오류 재현에 유용하지만 녹화 자체가 성능에 영향을 주므로 성능 수치 측정과
  분리한다. 동일 기기/전원·발열·주사율·데이터·네트워크 조건을 맞춘다.
