DavaQ 메시지 포커스·제스처·반응·다중 선택 / 실기기 검증
2026-10-17

구현 내용
- 메시지 본문 영역을 320ms 길게 누르면 화면 좌표를 측정한다. 배경을 어둡게 하고
  같은 본문의 미리보기를 전면에 표시한다. 위에는 반응 선택기, 아래에는 스크롤 가능한
  액션 메뉴를 표시한다. 긴 본문 미리보기는 화면 높이에 맞춰 잘라 표시한다.
- 화면 가장자리·안전 영역을 고려해 메뉴 위치를 보정한다. 원본 목록을 이동시키지 않아
  메뉴를 닫아도 읽던 메시지 위치를 유지한다. 바깥 탭/Android 뒤로가기로 닫는다.
- iOS의 신고·전달·스티커 선택기는 포커스 모달이 닫힌 후 표시한다.
- 기존 신고/삭제 권한을 유지한다. 상대 메시지를 모두에게 삭제하는 항목은 표시하지 않는다.
- 네이티브 메시지 본문 왼쪽 스와이프: 12pt부터 인식, 56pt에 진동, 손을 놓을 때 답장.
  56pt 안으로 되돌아온 뒤 놓거나 취소되면 답장하지 않는다. 수직 이동은 스크롤에 양보한다.
- 채팅 목록의 빈 배경에서 오른쪽 스와이프: 이전 화면으로 이동. 본문에서 시작한 터치,
  헤더/입력 영역/거래 카드/통화 카드의 터치는 배경 뒤로가기가 가져가지 않는다.
  기존 거리/속도 기준을 유지한다. 데스크톱 웹/임베디드 패널은 배경 뒤로가기를 적용하지 않는다.
  iOS에는 자체 배경 제스처를 사용하며 해당 라우트의 기본 스택 제스처 중복을 해제했다.
- 웹에서는 오른쪽 클릭 또는 Shift+F10으로 메뉴를 연다. 답장 스와이프는 네이티브에 적용한다.
- 이모지별 인원 수와 내 반응 강조를 표시한다. 기존 3개 표시 제한을 제거했다.
  같은 내 반응을 누르면 취소하고 다른 코드를 누르면 교체한다. 빠른 연타는 메시지별 잠금으로 제한한다.
- 서버 API의 POST .../sticker에 선택 필드 remove:boolean을 추가했다. 기본 false로
  기존 클라이언트의 추가/교체 의미를 유지한다. remove:true는 내 사용자ID와 해당 code가
  일치하는 반응만 삭제한다. 같은 제거 요청 재시도와 오래된 코드 제거는 안전하다.
- 반응은 서버 성공 후 목록을 갱신한다. 실패하면 기존 표시를 유지하고 오류를 안내한다.
  기존 message_stickers 변경 트리거가 DELETE도 포착하므로 새 마이그레이션은 필요 없다.
- 선택 메뉴에서 여러 메시지를 선택/해제하고 개수를 확인한다. 일괄 복사·전달·나에게만 삭제를
  제공한다. 복사/전달은 시간순이다. 삭제는 확인 창을 거친다. 선택 중 답장/반응/배경 이동은 막는다.
  취소/헤더 뒤로가기/Android 뒤로가기로 선택을 해제한다.
- 일괄 작업은 항목별로 성공을 반영한다. 실패한 항목부터 남겨 재시도한다. 전달은 같은
  작업 재시도에 동일한 clientMessageId를 사용한다. 계정·프로필·방이 바뀌면 후속 작업과
  이전 화면 상태 갱신을 중단한다. 일괄 전달은 지원되는 텍스트/사진/파일/스티커만 허용한다.

실행 준비

   remove:true를 처리하는 이번 서버 코드가 먼저 실행되어야 한다. 이전 서버는 필드를
   무시하고 반응을 다시 추가할 수 있다. 기존 변경 로그 마이그레이션 0046은 적용돼 있어야 한다.
2. 이번 작업은 로컬 코드/자동 검증까지 진행했다. 운영 서버나 스토어에 배포한 버전이 아니다.

3. Mac에서 프로젝트 기존 비공개 환경을 사용하고 EXPO_PUBLIC_API_BASE_URL이 위 테스트
   서버를 가리키는지 확인한다. 토큰/비밀번호를 출력하거나 공유할 필요는 없다.
   cd /Users/smileonlabs/Documents/davaq
   source .local/activate.sh
   pnpm --filter @workspace/mobile exec expo run:ios --device
   또는 pnpm --filter @workspace/mobile exec expo run:android --device
   Expo Go 대신 네이티브 개발 빌드를 사용한다. 최종 체감 성능은 같은 기기의 Release끼리 비교한다.
4. iOS와 Android 각각 아래를 실행한다. A계정은 기기와 다른 웹/기기에 동시에 로그인하고,
   B계정은 상대 역할로 로그인한다. 개인 대화 대신 전용 방을 사용한다.
   150개 이상의 텍스트, 긴 글, 사진, 파일, 스티커, 답장을 포함한 대화를 준비한다.

검증 1 / 포커스 메뉴
- 상대 메시지 본문을 길게 누른다. 해당 본문과 반응/메뉴만 선명하게 보이는지 확인한다.
- 화면 맨 위/맨 아래, 긴 본문, 사진/파일, 키보드가 열린 상태에서도 반복한다.
- 메뉴를 스크롤해 답장·복사·고정·전달·신고·선택·나에게만 삭제가 보이는지 확인한다.
  상대 메시지에는 모두에게 삭제가 없어야 한다. 내 메시지에는 신고가 없어야 한다.
- 바깥을 눌러 닫는다. 원래 읽던 메시지 위치와 입력 중인 문장이 유지돼야 한다.
- iOS에서 신고·전달·스티커를 열고 취소한다. 모달이 겹치거나 터치 불가 상태가 남지 않아야 한다.
- 메뉴가 열린 메시지를 B기기에서 모두에게 삭제한다. 동기화 후 메뉴가 닫혀야 한다.

검증 2 / 터치 대상과 방향
- 본문을 왼쪽으로 짧게 밀었다 놓는다: 원위치, 답장 없음.
- 본문을 왼쪽으로 충분히 밀고 놓는다: 진동 후 그 메시지의 답장 미리보기.
- 임계점 넘기기→되돌리기→다시 넘기기를 한 제스처로 한다: 진동 1회.
  임계점 안으로 돌아온 뒤 놓으면 답장하지 않아야 한다.
- 본문을 오른쪽으로 민다: 답장/배경 뒤로가기가 실행되지 않아야 한다.
- 본문 옆 빈 공간을 왼쪽으로 민다: 답장 없음.
- 빈 배경을 위아래/수직에 가까운 대각선으로 민다: 대화만 스크롤.
- 빈 배경을 오른쪽으로 짧게 밀면 취소, 충분히 밀면 이전 화면.
- 입력창·헤더 버튼·사진·거래/통화 카드에서의 조작이 배경 이동에 빼앗기지 않아야 한다.

검증 3 / 이모지 취소·집계·동기화
- A/B가 같은 메시지에 👍: 숫자 2. A의 기기/동일 계정 웹에서 내 반응 강조 확인.
- A가 👍를 다시 누름: A의 반응만 취소, 숫자 1. B 반응 유지.
- A가 ❤️를 선택하고 😂로 바꿈: A는 마지막 코드 하나만 남음.
- A의 두 기기에서 동시에 다른 코드를 고른 뒤 동기화: 서버 최종 상태로 수렴해야 한다.
- 인터넷을 끊은 상태에서 취소: 오류 안내 후 기존 표시가 유지돼야 한다.
  재연결 후 다시 취소해 정상 동작하는지 확인한다.
- A의 한 기기를 오프라인으로 두고 B가 반응 추가/교체/취소한다.
  A 재접속 후 숫자와 내 반응이 다른 기기와 일치해야 한다.

검증 4 / 다중 선택·부분 실패
- 메뉴의 선택을 누르고 3개를 추가 선택한다. 개수·체크 표시가 일치해야 한다.
- 선택한 메시지를 다시 눌러 해제하고 취소/뒤로가기로 선택 모드를 종료한다.
- 복사 결과가 시간순인지 확인한다. 지정한 다른 테스트 방으로 전달하여 순서/중복을 확인한다.
- 3개 이상 전달/삭제 도중 네트워크를 끊는다. 성공한 항목은 선택에서 빠지고,
  남은 항목만 재시도할 수 있어야 한다. 전달 재시도 때 이미 전달된 메시지 중복이 없어야 한다.
- 일괄 삭제는 나에게만 적용되고 B의 대화에는 원본이 남아야 한다.
- 처리 중 다른 방/프로필/계정으로 전환한다. 다음 메시지 작업이 이어지거나
  새 화면의 선택·메뉴를 이전 응답이 변경하지 않아야 한다.

검증 5 / 기존 기능 회귀
- 과거 100개 이상 위로 이동해 메뉴/반응/선택을 조작한다. 최신으로 강제 이동하지 않아야 한다.
- 방을 나갔다 다시 들어오고 앱을 종료/재실행한다. 읽던 메시지 부근으로 복원돼야 한다.
- A를 오프라인으로 만들고 고유 문구 메시지를 1개 전송한 뒤 앱을 종료한다.
  B에서 G1/G2/G3을 전송한다. A 재접속·재실행 후 A의 대기 메시지가 정확히 1개 도착하고
  G1/G2/G3이 순서대로 복구돼야 한다. 다른 A기기에도 같은 내역이 보여야 한다.
- 복구된 메시지에 답장/반응/선택 후 다시 새 메시지를 보낸다. 입력창·전송 상태가 정상이어야 한다.
- 마지막으로 과거 메시지의 수정/삭제·사진 로딩 중 메뉴를 닫았다 열어도 위치가 유지되는지 확인한다.
