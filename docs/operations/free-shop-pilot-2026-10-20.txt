DavaQ 무료 매장 모드 — 초기 구현 / 2026-10-20

목표
매입 업무 반복 사용과 정확한 카드별 매입 기록 확보. 개인 컬렉션·교환과 매장 자산은 분리한다.
현재 변경은 로컬 소스 구현이다. 운영 DB 마이그레이션, 운영 플래그 활성화, 네이티브 배포는 수행하지 않았다.

진입점
- 설정 > 무료 매장 모드, 채팅 > 매장 상담·무료 매장 모드
- /shop : 소속 매장, 고객 자신의 상담 목록, 개설·직원 초대 참여
- /shop/[shopId] : 매입 / 재고 / 고객 / 관리
- /shop/contact?shopId=<UUID> : 고객용 매장 정보와 상담 시작 (DavaQ 로그인 필요)
- /shop/conversation?shopId=<UUID>&threadId=<UUID> : 고객·직원 전용 상담

구현한 흐름
1. 매장 개설, 개인·매장 화면 전환, 점주·직원 권한, 24시간 일회용 직원 초대, 접근 해제.
2. 현장 고객 견적 생성. 기존 카탈로그와 사진 스캔 결과에서 카드 선택.
   기존 /tcg/scan을 열어 촬영한 뒤 돌아와 최근 결과를 선택하는 첫 연결이다.
   스캐너에서 견적에 바로 연속 추가하는 기능은 다음 단계이다.
3. 실물 판본 확인, 수량·상태·매입 단가·보관 위치·검수 이유 입력.
   서버에서 카드 정보를 다시 확인하고 참고 가격·판본 정보를 견적에 스냅샷으로 보존.
   점주가 카드별 기본 매입표를 저장. 원화 매입가는 외부 참고가에서 자동 환산하지 않는다.
4. 카드별 매입/반환 구분. 잘못된 항목은 초안에서 제거 후 재입력.
   점주가 고객 확인을 기록하고 확정하면 매입 대상만 입고.
   같은 확정 요청 재시도는 중복 입고하지 않는다. 다른 버전 수정은 충돌로 거절.
5. 지급은 미지급/직원이 지급 완료로 기록을 구분. 실제 결제·송금 검증이 아니다.
6. 입고 건별 원가 보존, 현장 판매·실사 수량 증감과 사유, CSV 내보내기.
   부족한 재고 차감 거절, 요청 키 재전송 중복 차감 방지.
7. 매장 전용 상담함. 고객과 해당 매장 직원만 접근. 개인 메신저 대화·컬렉션 접근 없음.
   고객은 자신의 매장 상담 목록을 다시 열 수 있다. 매장 답변은 매장 명의로 표시하고 실제 직원은 DB 기록.
8. 고객이 정확한 카드를 검색해 수량·희망 상한가를 등록하고 종료 가능.
   매장에는 카드 ID·수량 기준 재고 일치 후보 표시. 상태·판매가격 적합성은 별도 확인.
9. AI 상담 요약·답변 초안, 재고 최대 10건의 가격 없는 입고 홍보 초안.
   상담은 고객의 동의와 직원의 외부 AI 전송 확인 후 최근 메시지 최대 20건만 사용.
   개인 대화는 사용하지 않는다. 상담에 연결된 고객 요청과 재고 수량만 보조 자료로 사용.
   직원 검토 후 수동 전송. 요약은 내부 초안이며 자동 발송·예약·판매 실행 없음.
   한국 시간 날짜 기준 매장당 일 20회, 영속 DB 카운터. 실패한 API 요청도 한도를 소비.
   모델: TCG_AI_MODEL 또는 기존 기본 모델. 기존 AI 연결 설정 사용.

활성화
- 기본 DAVAQ_SHOPS_ENABLED=false. false면 UI 진입점 숨김, config 이외 매장 API 404.
- lib/db/drizzle/0052_davaq_shops.sql 및 migration journal 항목 추가.
- 기존 migration journal에는 0048~0051 항목이 없는 상태였음. 이 변경에서 그 별도 기능의
  운영 migration 이력을 임의로 재구성하지 않음. 운영 적용 전 실제 DB migration 이력 확인 필요.
- 격리된 스테이징 DB에 마이그레이션 후 권한·스캐너·기기별 UI 검증.
- 파일럿은 배포 접근이 제한된 스테이징에서 진행할 것.
  현재 플래그는 전역이다. true인 서버에서는 모든 로그인 사용자가 계정당 최대 3개 매장 개설 가능.
  일반 공개 전에 매장 허용 목록 또는 운영자 승인 절차를 추가할 것.
- 데이터베이스 백업·migration 확인 후 파일럿 환경에서만 플래그 활성화.
- 플래그 false로 내려도 데이터는 삭제하지 않는다.

검증
- PGlite + Express 실제 라우트 통합 테스트 15개 통과. 외부 AI와 카드 카탈로그는 모의 응답.
- 권한 격리·타 매장 견적 접근·직원 제거·초대 재사용·견적 버전 충돌·부분 매입·중복 입고·재고 부족·
  중복 차감·지급 상태·취소·상담 격리·메시지 재전송·고객 상담함·AI 동의·일일 한도·매칭·CSV 검증.
- API 및 mobile TypeScript 검사 통과. API esbuild 빌드 통과.
- 새 /shops 경로는 OpenAPI에 명시. 기존 다른 39개 경로 미문서화 때문에 전체 route coverage 검사는 실패.
  새 매장 경로의 coverage 누락은 없음. 생성 SDK 재생성은 이번 단계에서 하지 않음 (UI는 기존 customFetch 사용).
- 실제 PostgreSQL 동시 접속 테스트, 네이티브 스캔, 실제 AI, 브라우저·물리 기기 시각 검증은 미완료.

알려진 범위와 다음 순서
1. 파일럿 매장 허용 목록·정확한 카드 판본/가격 품질·실물 기기 UI 검증.
2. 스캐너 결과를 견적에 바로 연속 추가, 등록 사진과 직원 판본 수정 이력 연결.
3. 매입 확정 취소/반품·지급 반환까지 포함한 전용 정정 흐름.
   현재 확정 견적은 불변이며 재고 증감 정정만 가능. 지급 반환·원가 정정 업무를 대신하지 않는다.
4. 매장 상담은 별도 테넌트 권한 테이블을 사용한다. 기존 개인 채팅방에 직원 전체를 넣지 않았다.
   같은 로그인·공통 UI·AI 클라이언트를 활용하되 상담 전송은 별도 API이다.
   현재 열려 있는 상담은 10초 갱신. 실시간 전송, 푸시·읽음·미확인 수, 기존 메신저 사진 첨부·차단·신고 연동은 후속.
5. 상담 담당자 지정·직원 내부 메모·고객에게 견적 링크/상품 카드 공유.
6. 고객 요청에 조건·만료 추가, 입고 안내 초안·승인 발송·수신 거부 정책.
   현재 자동 마케팅 발송, 연락처 가져오기, 사적인 고객 프로필 추론 없음.
7. 판매가격·예약 확보/만료·고객 구매 확인을 추가한 뒤 판매 전환 분석.
   현재 재고 차감은 판매 대금이나 매출을 증명하지 않음.
8. 조회 한도: 견적/상담/고객 요청 최근 100건, 재고/매입표 500건, 메시지 최근 100건,
   견적 항목 200개, CSV 최대 10,000 입고 건. 페이지네이션은 다음 단계.
9. 별도 기여 동의·보존/삭제 정책·내보내기·중복 제거 설계 후 익명 통계/인식 개선 데이터 사용.
   현재 로그는 업무 운영용이며 자동 모델 학습·공개 시세로 제공하지 않는다.

초기 파일럿 기준
적합 매장 3~5곳에서 실제 매입 사례로 처리 시간과 확정 기록의 정확성 비교.
주간 반복 사용 매장 수, 최종 상태까지 처리한 견적 비율, 판본·상태가 확인된 확정 항목 수,
지원 시간과 AI 비용, 고객 상담 재사용을 측정한다. 조회·견적·확정 매입·지급 기록·판매는 섞지 않는다.
