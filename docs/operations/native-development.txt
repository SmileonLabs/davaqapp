DavaQ native development — phase 1

From the repository root:
  source .local/activate.sh       (this machine's bundled Node/pnpm)
  pnpm install --frozen-lockfile

Copy artifacts/mobile/native.env.example to artifacts/mobile/.env.local and fill
in a development Clerk key, reachable development API URL, and DavaQ Firebase
app files. Android Firebase package and iOS bundle ID must be app.davaq.mobile.
Do not use a Firebase service-account JSON as google-services.json: the service
account is server-only. Upload APNs credentials to Firebase for ordinary iOS push.
VoIP PushKit credentials and delivery will be implemented separately.

Commands (from repository root):
  pnpm --filter @workspace/mobile native:doctor ios
  pnpm --filter @workspace/mobile native:doctor android
  pnpm --filter @workspace/mobile native:doctor ios --cloud
  pnpm --filter @workspace/mobile native:prebuild --platform ios
  pnpm --filter @workspace/mobile native:ios
  pnpm --filter @workspace/mobile native:android
  pnpm --filter @workspace/mobile dev:native

Local iOS needs Xcode, CocoaPods and a simulator or provisioned device.
The Clerk native SDK requires iOS 17 or later; its official plugin sets this target.
Local Android needs JDK 17 and Android Studio SDK, ANDROID_HOME and a device/emulator.
Native folders are generated by Expo and ignored; make durable changes in config/plugins.
Expo Go cannot load this app's custom Firebase/WebRTC/foreground-service modules.

EAS commands must run inside artifacts/mobile (not the repository root):
  eas build --platform ios --profile development-simulator
  eas build --platform ios --profile development
  eas build --platform android --profile development
Use a configured EAS CLI and your DavaQ project. Set EAS_PROJECT_ID, the public
Clerk/API variables and Firebase file variables in the development EAS environment.
The development profile intentionally has no production API override.
Cloud builds are not triggered automatically by setup commands.

Notifee incoming-call UI remains active until that replacement is validated.

Real-device acceptance matrix:
- foreground, background, locked, OS-terminated app (force-stop separately)
- incoming accept/decline, caller cancellation, expired and duplicate push
- simultaneous response on two signed-in devices
- Wi-Fi/mobile switch and brief disconnection
- Bluetooth/headset changes and interruption by a cellular call
- logout/account switch and previous-account notification cleanup
Record OS/device/build, call ID, push receipt, UI display, answer and media times.

Message/call audit and read-receipt correction (2026-10-10):

  actually viewable row. Read receipts now require foreground, focused, ready

  document.hasFocus and synchronous lifecycle gates now prevent hidden reads.
