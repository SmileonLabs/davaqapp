DavaQ card discovery feed — 2026-10-15

Requested behavior
- The exchange feed includes catalog cards even when no user owns or publicly offers them.
- Active public offer cards appear first, followed by general catalog cards. Both buckets
  use a viewer/session seed. Paging keeps the order; explicit refresh starts a new order.
- One canonical card appears once. Its real public listings are grouped under that card.
- An unlisted card can be liked/commented on and offers an "I have this card" registration path.

Implementation
- Added /api/tcg/card-feed and per-card offers/likes/comments while retaining the old listing
  feed and trade UUID endpoints for installed clients. Canonical storage identity uses saveId.
- API cursors are scoped to viewer, filters and a 30-minute snapshot. The server traverses
  catalog pages with a seeded coprime permutation and shuffles cards within pages, with
  seen-card deduplication. This is diverse ordering, not a uniform shuffle of the entire catalog.
- Catalog HTTP work runs outside database transactions; bounded request budgets, page cache
  and in-flight deduplication prevent downloading the whole catalog in advance.
- The client prepares up to 60 metadata rows when possible, preloads the current/next three/
  previous one image with concurrency two, and preserves confirmed social writes when an
  older next-page response finishes. Healthy empty-page continuation is bounded; partial
  source failures keep existing cards and provide manual retry.
- Additive migration 0044 creates card social/catalog/snapshot tables and preserves legacy
  likes/comments. Legacy comment timestamps are copied directly in SQL, retaining microseconds.
