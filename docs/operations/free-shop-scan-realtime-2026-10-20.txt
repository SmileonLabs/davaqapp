DavaQ 무료 매장 모드 — 스캔 견적 직접 연결 / 상담 실시간·푸시 (2026-10-20)

구현 범위
1. 매입 견적 > 스캔해서 이 견적에 바로 추가 > 사진 촬영·선택 또는 네이티브 실시간 스캐너.
   사진 결과의 '이 견적에 추가' / 실시간 스캐너의 카드 열기 → 동일 견적 확인 화면.
   실물 판본·상태·수량·매입 단가 확인 → 견적에 담기 → 같은 견적에서 다음 스캔.
   견적 전체 보기로 돌아가도 견적 선택 유지. 웹은 사진 업로드 방식, 네이티브는 기존 카메라 스캐너 재사용.
   스캔 인식만으로 매입이나 재고 입고를 실행하지 않는다.
2. 사진 스캔 ID·인식 카드 ID·직원이 선택한 카드 정보를 견적 스냅샷에 기록.
   본인의 인식 완료 스캔만 연결할 수 있다. 개인 컬렉션에는 자동 등록하지 않는다.
   네이티브 실시간 스캔은 기존 엔진의 카드 ID를 사용하며 서버 사진 기록이 없으면 source_scan_id는 비어 있다.
3. 견적 항목 요청 키로 네트워크 재시도 시 중복 추가 방지. 같은 키로 다른 내용이면 409.
   다른 직원이 변경한 견적은 버전 충돌을 표시한다. 새 항목 등록에는 현재 견적 버전 필요.
4. 매장 상담 메시지와 수신자별 전송 작업을 한 트랜잭션에서 저장.
   메시지 요청 재전송은 기존 메시지를 반환하고 전송 작업을 중복 생성하지 않는다.
5. 기존 DavaQ WebSocket/Redis 채널에 shop.message.created / shop.thread.updated 이벤트 추가.
   이벤트에는 매장·상담·메시지 ID만 포함. 메시지 본문은 인증된 상담 API에서 다시 조회.
   접속 복구 시 매장 쿼리 갱신, 화면 복귀·30초 폴링은 장애 복구용으로 유지.
6. 기존 APNs / FCM / 웹 푸시 전송 함수를 재사용.
   '매장 상담에 새 메시지'라는 일반 알림과 /shop/conversation 딥링크만 전송.
   기존 계정별 푸시 소유권 검증과 전체 알림 설정을 유지하며 강제 알림(force)은 사용하지 않음.
   네이티브 전경 푸시와 웹 Service Worker 이벤트로 상담 쿼리도 갱신.
7. 사용자별 읽음 커서와 상담별 알림 끄기. 열린 화면에서 실제 불러온 메시지까지 읽음 기록.
   오래된 읽음 요청은 커서를 되돌리지 않으며, 미래 커서는 서버 최신 메시지까지 제한.
   고객/직원 상담 목록에 미확인 수 표시. 읽음은 사용자별이므로 한 직원의 읽음이 다른 직원에게 적용되지 않음.
8. 전송 작업은 발신자에게 푸시하지 않고, 처리 시점에 직원 소속·고객 접근·읽음·알림 끄기를 재검사.
   푸시는 메시지 저장 후 3초 지연해 즉시 읽은 메시지의 불필요한 알림 감소.
   독립 realtime/push 작업, 2분 임대, 지수 백오프(최대 5분), 실패 10회 후 failed_at 기록.
   프로세스 중단 뒤 임대 만료로 재처리. 전송은 at-least-once이며 외부 제공자의 기기 수신 보장은 아님.
   알림 태그는 상담별 고정. delivered_at은 작업 처리 완료이며 실제 화면 열람/수신 증명이 아니다.

1. 운영 변경을 보존하고 별도 스테이징 DB 백업/마이그레이션 이력 확인.
