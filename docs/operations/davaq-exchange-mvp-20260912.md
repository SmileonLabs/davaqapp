## 이번 구현

- 밝은 DavaQ 디자인과 홈 / 둘러보기 / 채팅 / 내 AI / 내 교환의 다섯 메뉴. 교환 등록, 상세, 매칭 이유, 제안·협상, 큐 대화·기억·설정·탐색 기록, 계정 및 관리자 검토 화면.
- 실제 등록 데이터 기반 검색·필터·관심 저장·쌍방 희망 매칭. AI 초안과 수동 편집, 비공개 임시 저장, 사진 업로드, 검토 대기 상태.
- 버전이 있는 교환 제안과 채팅 카드, 양쪽 명시적 동의, 상품·양쪽 참여자 시간 중복 예약 방지, 각자 제공·수령 확인, 취소·분쟁·후기. 확정 후 일정 변경은 합의 취소 후 새 제안으로 처리한다.
- 큐 전용 대화, 확인할 기억 후보, 확인한 기억의 수정·삭제·만료. 활동·대화 학습과 자동 탐색은 기본 꺼짐. 선택한 대화방에서 동의 이후 본인이 보낸 메시지만 사용하며 상대방 메시지나 AnotherMe 데이터는 가져오지 않는다.
- 실제 확인한 기억과 완료 교환 이벤트로 표시하는 3단계 성장 여정. 새 조건에 따른 제한된 자동 탐색 작업 및 실제 탐색 기록. AI는 공개·상대에게 제안 전송·교환 수락 권한을 갖지 않는다.
- CEO Voice / Business Mentoring / Executive Dinner는 본인이 제공 가능 여부를 검토하고 수정하는 등록 템플릿이다. 실재 공급자의 공개 상품이나 성사된 교환으로 채우지 않았다. EV는 참고값이며 결제·잔액·현금화 기능은 없다.
- 기존 RPG·지갑 중심의 기본 화면과 자동 페르소나 학습 경로를 DavaQ 기본 흐름에서 제거했다. 호환용 레거시 코드 일부는 저장소와 웹 번들에 남아 있다.

## 분리와 배포

Clerk 로그인 계정과 승인된 OpenAI·LiveKit·검색 API 자격증명만 기존 서비스를 재사용한다. DavaQ DB·역할, Redis, Neo4j, S3, 소스 및 서비스 프로세스는 별도다. 공유 제공자의 사용량·비용은 같은 계정에 합산된다.

추가형 DB migration 0029~0032를 적용했다. 배포 전에 DavaQ DB만 pg_dump custom 형식으로 백업하고 크기 및 pg_restore --list로 백업 목록을 검증했다. 전체 복원 리허설을 수행했다는 의미는 아니다. 환경설정 백업은 서버에서만 권한 600으로 보관한다.

검토한 docker/deploy-davaq-mvp.py는 DB 이름·역할과 이미지 이름을 검사하고, 안전한 아카이브 추출·백업·마이그레이션 후 DavaQ app/web만 교체한다. 실행 실패 시 환경 백업으로 이전 앱·웹을 복구한다. 추가형 테이블은 그대로 두며 DB 자동 되돌리기는 하지 않는다. Compose와 Docker의 환경값 따옴표 처리 및 pg_dump의 URL 호환성 차이를 반영했고 명령 실패 출력은 비밀값을 마스킹한다.

공용 프록시·AnotherMe 컨테이너·AnotherMe 데이터베이스는 이번 MVP 배포에서 변경하지 않았다. 배포 전후 양쪽 health가 200, DavaQ 교환 API의 비로그인 요청이 401임을 확인했다.

## 검증 결과와 범위

- 최초 로컬 API 검사 100 통과, 인프라 조건 2개 건너뜀. 최종 CI에서는 PostgreSQL·Redis 인프라 검사와 교환 사진 권한 검사를 포함해 API 테스트 113개가 전부 통과했다. 사진은 미공개 업로드·초안·공개·차단·교환 당사자 상태별로 접근을 검증했다.
- 메신저·통화·PWA 관련 회귀 테스트 63 통과. 아이콘 경로 변경 후 PWA 캐시·알림 소유자 테스트 7개 추가 재실행 통과(63개에 포함되는 항목).
- 실제 PostgreSQL의 임시 격리 스키마에서 API 통합 검사 30 통과. 임시 계정·데이터는 종료 시 해당 스키마와 함께 삭제했다. 로그인 경계는 테스트용 인증 주입이며 실제 Clerk 로그인 테스트와 구분한다. 외부 푸시·실시간 전송 경계도 테스트 대역을 썼다.
- 통합 검사는 중복 요청, 익명·타인 접근, 비공개 초안, 상호 매칭, 동시 수락, 양쪽 일정 충돌, 불완전 이행, 버전 변경, 관리자 읽기 권한, 학습 범위·동의 버전·기억 삭제를 확인했다. 이 중 2개는 실제 OpenAI 호출로 초안과 한국어 답변을 확인했다.
- API·모바일·랜딩 및 공유 라이브러리 TypeScript 검사, OpenAPI coverage, 생성된 클라이언트·Zod 재생성 일치 검사 통과. API·랜딩·PWA 운영 빌드 통과.
- 운영 도메인의 실제 로그인 세션에서 다섯 탭, 교환 등록, 큐 대화·기억·학습 설정을 점검했다. 실제 AI 초안이 폼을 채우는 것을 확인했고 검증 초안은 저장·공개하지 않았다. 320px 등록 폼, 360/390/430px 주요 모바일 화면 및 1365px PC 랜딩에서 표시를 확인했다. 발견한 하단 메뉴 글자 잘림·인사말 줄바꿈은 수정 후 재확인했다.
- 새 사용자의 화면은 실제 빈 데이터 상태다. 임의의 상품·거래·후기·성장 수치를 운영 DB에 넣지 않았다.

## 파일럿 및 후속 범위

첫 버전은 2자 교환 PWA다. 3/4자 연쇄 교환, 완전 자동 상대 연락·협상, 그룹 Experience, 더 다양한 큐 외형, 앱스토어 출시는 후속 범위다.

이 릴리스에서 두 실제 Clerk 계정이 브라우저로 상품을 공개하고 제안부터 완료까지 수행하는 전체 사용자 시나리오, 두 실기기의 음성·영상 통화와 백그라운드 푸시·설치 동작, 실제 공급자 검증 및 분쟁 운영 파일럿은 수행하지 않았다. API의 격리 계정 통합 검사가 이를 전부 대체하지는 않는다. 기존 자산·레거시 의존성이 남아 있는 웹 초기 번들 크기는 다음 성능 개선 대상이다.
