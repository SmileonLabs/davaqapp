DavaQ media UX implementation — 2026-10-12

Implemented
- Full-screen photo, video and send-preview modals have their own safe-area provider. Close controls sit below top safe area (minimum iOS fallback 44 + 8 px), with a 48 px minimum hit target.
- Photo library selection (up to 10), direct camera capture, preview, ordering, removal, 90-degree rotation, center square crop, caption and original/compressed choice.
- Standard photos become JPEG at quality .78, maximum long edge 2048; GIF/original mode preserves source format. Web HEIC is converted before processing. A bounded inline JPEG preview avoids waiting for the private full-image URL before showing something.
- Each uploaded photo is queued immediately instead of waiting for the complete selection. Local upload previews/progress and cancellation are visible. Partial failures retain only unsent items for retry during the current app session.
- Albums use occupied rows only, support 1/2/3/5/10 items and preserve selection order. Underlying messages still reference separately authorized object paths. The highest committed room sequence represents the album for read tracking; replies/unread markers map to that visible representative.
- Gallery supports album paging, iOS native zoom, Android pinch/double tap/pan, web double click/trackpad zoom/drag, and platform sharing/save UI.
- Video library/camera, send preview, caption, inline poster/duration, and native in-chat playback. Native video compression uses maxSize 1280 and leaves files under 2 MB unchanged; original is optional. Browser video remains original, explicitly stated in the preview.
- Web pasted/dropped photos receive compression and album metadata. Cancelling/failing a file batch stops the remaining files.
- Owner/profile/room changes clear local previews/retry UI and preserve existing abort/owner fences. Outbox persists album/preview metadata through message retries.
- Android manifest retains allowBackup=false despite a transitive media dependency declaring true. Native dependency pinned to react-native-compressor 1.19.4.

Limits / release status
- Existing upload limits remain 10 MB/photo after processing and 25 MB/video/file.
- Browser video transcoding is not provided. Native video transcodes via the platform library; source codec/real-device behavior still needs device checks.
- Uploads interrupted by force-quitting the app are not a durable background upload queue. Successfully uploaded/queued messages use the existing durable, idempotent outbox; unfinished local upload selections are retained only within the current app session.
- No new iOS archive, physical iPhone/Android camera test, store upload or production web deployment has been performed for this change.
